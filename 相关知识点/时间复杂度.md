## 时间复杂度
### 时间复杂度定义
时间复杂度是指算法的时间开销函数，表示随问题规模N的增大，算法执行时间的增长率和f(N)的增长率相同，称作算法的渐进时间复杂度，简称为时间复杂度。其中f(N)是问题规模N的某个函数。

### 时间复杂度分类
1. 常数阶O($1$)
2. 对数阶O($log_2N$)
3. 线性阶O($N$)
4. 线性对数阶O($Nlog_2N$)
5. 平方阶O($N^2$)

### 时间复杂度计算 cpp
1. 常数阶O($1$)
```cpp
void fun1(int n) {
    printf("hello world");
}
```
2. 对数阶O($log_2N$)
```cpp
void fun2(int n) {
    for (int i = 1; i < n; i *= 2) {
        printf("hello world");
    }
}
```
3. 线性阶O($N$)
```cpp
void fun3(int n) {
    for (int i = 0; i < n; i++) {
        printf("hello world");
    }
```

```cpp
void fun4(int n) {
```

# 时间复杂度（通俗理解）
**时间复杂度不是程序实际跑了多少秒，而是：当输入数据规模变大时，你的算法需要执行的操作次数增长有多快。**
> 记法：$O(...)$，读作「大O记号」

## 核心一句话
它看的是**增长趋势**，不精确统计一共多少行代码，只关心：**输入n变大，运算次数怎么涨**。

## 常见几种，从快到慢
1. $O(1)$ 常数复杂度
不管n多大，**执行次数固定不变**。
例子：取两个数做减法、三元运算符、单次if判断。
> n=1万 和 n=1，运算次数一样。

2. $O(n)$ 线性复杂度
输入规模n扩大几倍，操作次数就扩大几倍。
例子：循环遍历一遍所有数字（找最大值最小值），循环跑n次。
n=1e5，循环大约1e5次；n=2e5，循环大约2e5次。

3. $O(n\log n)$
典型：sort排序。n翻倍，操作次数不会直接翻倍，涨得比$\(O(n)\)$快、比$O(n^2)$慢。

4. $O(n^2)$ 平方复杂度
两层嵌套循环。n扩大2倍，操作次数大约变成4倍。
> ❗坑：n=1e5的时候，$O(n^2)$ 会有 $10^{10}$次运算，**直接超时**，绝对不能用。

5. $O(2^n)$ 指数级（极慢，n稍微大就炸）

## 举你刚才那道题的例子
题目：n个数字，找最大值最小值
- 方案A：一遍循环读入，同时记录max、min，循环只跑1次 → $O(n)$ ✅，n=1e5轻松过
- 方案B：写双重循环，两两枚举所有数算差值 → $O(n^2)$ ❌，n=1e5直接TLE

> 注意：`ios::sync_with_stdio(false);` **不改变时间复杂度！**
> 它只加速IO，不会减少循环次数，算法本身复杂度不变。

## 3个重要误区
1. ❌ 误区：代码行数越多，复杂度越高
> 不是。哪怕循环里面写100行，只要循环跑n次，依然是$O(n)$。

2. ❌ 误区：时间复杂度=程序运行秒数
> 不是。秒数受电脑、cin速度、语言影响；复杂度只看**输入规模增大后的增长趋势**。
> 同样$O(n)$，加IO加速只是跑得更快，但复杂度还是$O(n)$。

3. ❌ 误区：常数要写进大O
> $O(2n+5)$ 直接简写为$O(n)$，常数全部忽略，只保留最高次项。
> 因为n很大时，常数2、+5几乎不影响增长趋势。

## 快速判断小技巧
- 单层for循环：大多 $O(n)$
- 两层嵌套for循环：大多 $O(n^2)$
- sort排序：$O(n\log n)$
- 没有循环：$O(1)$
